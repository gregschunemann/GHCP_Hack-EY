# Documentation Challenges

Generate and improve project documentation with AI assistance. These challenges cover everything from high-level READMEs and API docs to inline code comments and developer onboarding guides.

## When to Use These Challenges

Pick these if your team wants to:
- Improve or create your project's README and API documentation
- Add inline documentation (JSDoc, docstrings, XML comments) to undocumented code
- Generate a developer onboarding guide for your repository

## Challenges

| Challenge | Difficulty | Time | Description |
|-----------|-----------|------|-------------|
| [README & API Docs](challenge-1-readme-and-api-docs.md) | Beginner | 30-45 min | Generate or improve project-level documentation |
| [Inline Docs & Comments](challenge-2-inline-docs-and-comments.md) | Beginner | 30-45 min | Add documentation comments to undocumented code |
| [Onboarding Guide](challenge-3-onboarding-guide.md) | Intermediate | 45-60 min | Create a developer onboarding guide for your repo |

## Key Copilot Features for This Track

- **`/doc` slash command** — Quick inline documentation generation
- **`@workspace`** — Enables Copilot to understand and document the full project
- **Inline Chat** (`Ctrl+I`) — Add docs to selected code in context
- **Chat** (`Ctrl+Alt+I`) — Generate longer documentation like READMEs, guides, and API specs

## AI-Assisted Dev Kit Resources

If you've added the [AI-Assisted Dev Kit](../resources/AI-assisted_dev_kit/) to your repository, these resources are especially useful for this track:

| Resource | Type | How to Use |
|----------|------|------------|
| `/analyze-product` | Prompt | Run first to analyze your codebase and auto-generate `copilot-instructions.md` — Copilot then produces documentation consistent with your actual tech stack and standards |
| `templates/` | Templates | Use `code-style.md`, `best-practices.md`, and `tech-stack.md` as starting points for your project's documentation |
| `/generate-report` | Prompt | Generate a structured status or progress report for your project |

> **Tip:** Running `/analyze-product` before the documentation challenges saves significant time — it generates `copilot-instructions.md` with your project's structure automatically, giving Copilot the context it needs to produce accurate, project-specific docs.

## Tips

- **Documentation generated by AI still needs human review** — Check for accuracy, tone, and completeness
- **Provide examples** — Reference existing documentation in your project so Copilot matches the style
- **Focus on the "why", not just the "what"** — Copilot can describe what code does; you need to add *why* it was designed that way
- **Keep it maintainable** — Overly detailed docs become stale. Strike a balance between helpful and sustainable
